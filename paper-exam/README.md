# 선행연구 분석 수행평가 웹앱 (가안)

반별로 A·B·C형 논문 중 하나를 배정하고, 학생은 왼쪽에서 논문을 넘기고 확대하며 오른쪽에 11개 문항 답안을 작성합니다. 교사는 답안을 한 화면의 스프레드시트로 보고, 채점 기준별로 체크한 뒤 엑셀로 내려받습니다.

## 구성 파일

| 파일 | 역할 |
|---|---|
| `index.html` | 학생 화면 (로그인 → 대기 → 논문 열람·답안 작성 → 제출) |
| `teacher.html` | 교사 화면 (형 배정·시험 시작/종료, 답안 스프레드시트, 채점, 엑셀) |
| `config.js` | Firebase 설정, 형별 논문 정보, 문항, 점수표 |
| `db.js` | 데이터 저장 연결 (Firebase 또는 데모 모드) |
| `style.css` | 화면 디자인 |
| `papers/A.pdf, B.pdf, C.pdf` | **암호가 걸린** 논문 파일 (암호 없이는 열리지 않음) |
| `database.rules.json` | Firebase 보안 규칙 (관리 교사 이메일 포함, 저장소에 올리지 않음) |

`keys.txt`(논문 열람 암호)는 **GitHub에 올리지 마세요.** 교사 화면 › 설정에서 한 번 등록하면 됩니다.

## 논문 보호 방식 (무료)

1. 논문 PDF는 AES-256 암호로 잠근 상태로 GitHub에 올라갑니다. 누가 파일을 내려받아도 암호 없이는 열 수 없습니다.
2. 암호는 Firebase 데이터베이스에만 저장됩니다.
3. 교사가 어느 반의 **시험 시작**을 누르면, 그 반에 배정된 형의 암호만 학생 앱이 읽을 수 있게 됩니다.
4. 학생 앱이 암호를 받아 자동으로 논문을 열기 때문에 학생은 암호를 보지 못합니다.
5. 같은 형을 쓰는 반이 모두 **시험 종료**되면 다시 잠깁니다.

## 처음 한 번만 하는 설정 (약 20분)

### 1. Firebase 프로젝트 준비
기존 수업 게임 앱과 규칙이 섞이지 않도록 **이 평가용 새 프로젝트를 만드는 것을 권장**합니다. (Spark 무료 요금제로 충분)

1. https://console.firebase.google.com 에서 프로젝트 추가
2. **빌드 › Realtime Database › 데이터베이스 만들기** (위치: 싱가포르 asia-southeast1 권장, 잠금 모드로 시작)
3. **빌드 › Authentication › 시작하기 › 로그인 방법**에서 두 가지를 사용 설정
   - **익명** (학생용)
   - **Google** (교사용)
4. **Authentication › 설정 › 승인된 도메인**에 GitHub Pages 주소 추가 (예: `ddmong88-collab.github.io`)
5. **프로젝트 설정 › 내 앱 › 웹 앱 추가** 후 나오는 `firebaseConfig` 값을 복사

> 기존 프로젝트를 그대로 쓰려면, 규칙 탭의 기존 내용을 지우지 말고 `database.rules.json`의 `"paperExam2026": { ... }` 부분만 기존 `"rules"` 안에 추가해야 합니다. 통째로 덮어쓰면 기존 게임 앱이 작동하지 않습니다.

### 2. config.js 수정
- `firebaseConfig`에 복사한 값 붙여넣기
- 교사 이메일은 공개 저장소에 드러나지 않도록 config.js에 적지 않고, Firebase 보안 규칙에만 넣습니다.

### 3. 보안 규칙 게시
- `database.rules.json`의 `teacher@example.com`을 선생님 이메일로 바꿉니다.
  (또는 교사 화면 › 설정 › Firebase 보안 규칙에서 이메일이 반영된 규칙을 바로 복사할 수 있습니다.)
- Firebase 콘솔 › Realtime Database › **규칙** 탭에 붙여넣고 **게시**

### 4. GitHub에 올리기
- `keys.txt`와 `database.rules.json`(교사 이메일 포함)을 **제외한** 모든 파일을 저장소의 새 폴더(예: `sso4/paper-exam/`)에 올립니다.
- 학생 주소: `https://ddmong88-collab.github.io/sso4/paper-exam/`
- 교사 주소: `https://ddmong88-collab.github.io/sso4/paper-exam/teacher.html`

### 5. 열람 암호 등록
교사 화면 › **설정** › 논문 열람 암호 등록에서 `keys.txt`의 A·B·C 암호를 붙여넣고 각각 저장합니다.

## 수업 시간 운영

1. 교사 화면 › 시험 운영 › **형 랜덤 배정** (12개 반에 4·4·4로 고르게 배정, 직접 바꿀 수도 있음)
2. 수업 시작 시 해당 반의 **시험 시작**
3. 학생은 학생 주소에 접속해 학번(5자리)과 이름으로 입장 → 배정된 논문과 문항이 자동으로 열림
4. 수업 종료 시 **시험 종료** → 학생 화면이 잠기고 저장도 멈춤
5. 답안·채점 탭에서 확인, 채점, 엑셀로 내려받기

### 자주 생기는 상황
- **학생이 컴퓨터를 바꿔야 할 때**: 답안·채점 › 학생 행 클릭 › 관리 › **기기 변경 허용** → 학생이 새 기기에서 다시 입장하면 이어서 작성
- **실수로 제출했을 때**: 같은 곳에서 **제출 취소** (시험이 열려 있어야 수정 가능)
- **인터넷이 잠깐 끊겼을 때**: 답안은 학생 브라우저에도 백업되어, 다시 연결되면 자동 저장됩니다.

## 채점

학생 행을 누르면 문항별 답안과 평가계획서의 채점 기준이 함께 보이고, **기준 충족**을 체크하면 점수가 자동 계산됩니다.
- 과정(10점): 3개 충족 10 / 2개 8 / 1개 6 / 0개 4
- 탐구(25점): 8개 25 / 7개 23 / … / 1개 11 / 0개 9
- 특수 처리: 미응시·백지 11점, 장기 미인정 결석 10점
- 교사 관찰 메모: 질의응답 내용 등 세특 작성용 메모 (학생에게 보이지 않음)

엑셀 파일에는 학생별 전체 답안, 문항별 채점(O), 과정·탐구·총점, 이탈 횟수, 교사 메모가 한 시트에 담깁니다.

## 미리 체험하기 (데모 모드)
`config.js`의 apiKey가 `YOUR_`로 시작하는 동안은 데모 모드입니다. 같은 브라우저에서 `teacher.html`과 `index.html`을 각각 다른 탭으로 열어 흐름을 체험할 수 있습니다. (로컬 파일을 바로 열면 PDF가 열리지 않으므로 GitHub Pages나 간단한 웹 서버로 열어야 합니다.)

## 한계와 유의점
- 시험 중 화면을 사진으로 찍는 것까지는 막을 수 없습니다. 이 방식은 **시험 전 논문 유출**을 막는 장치입니다.
- 다른 창·탭 이동은 막지 않고 **횟수만 기록**합니다. 붙여넣기 차단은 설정에서 켤 수 있습니다.
- 같은 형을 쓰는 반이 동시에 열려 있는 동안은 그 형의 암호를 읽을 수 있습니다. 시험이 끝나면 꼭 종료해 주세요.

## 학생 이름 보호 (명렬표 대조)
- 학생은 학번과 이름을 입력하지만, 서버에는 이름 대신 알아볼 수 없는 코드만 저장됩니다.
- 교사 화면 › 설정 › 명렬표 불러오기에서 엑셀(학번·이름 또는 반·번호·성명 열)이나 붙여넣기로 명렬표를 넣으면, 이름이 표시되고 이름을 잘못 입력한 학생은 ‘이름 불일치’로 표시됩니다.
- 명렬표는 그 컴퓨터의 브라우저에만 저장됩니다. 다른 컴퓨터에서는 다시 불러와야 합니다.

## 여러 선생님이 함께 쓰기
- 다른 선생님이 교사 화면에 Google 계정으로 로그인하면 ‘등록 요청’을 보낼 수 있습니다.
- 관리 교사(보안 규칙에 이메일이 등록된 계정)가 설정 › 교사 관리에서 승인하면 바로 사용할 수 있습니다.
- 성적 처리 후 관리 교사가 설정 › ‘전체 답안·채점 기록 삭제’로 서버 데이터를 지웁니다.

## AI 1차 채점 결과 불러오기
- 답안·채점 탭 › **엑셀로 내려받기** → 이름 열을 지운 파일을 Claude 대화에 올려 1차 채점을 요청합니다.
- 돌려받은 파일(학번, `[채점] 과정 ①`… 열에 O / ? / X / O★, `[근거] 과정 ①`… 열에 판단 이유)을 **채점 결과 불러오기**로 반영합니다.
- `?`는 ‘확인 필요’로 체크하지 않은 채 주황색 테두리로 표시됩니다. 교사가 ‘기준 충족’을 체크하거나 ‘미충족으로 판단’을 누르면 표시가 사라집니다.
- `★`는 세특 작성에 활용할 우수 사례입니다. 교사 화면에서도 문항별로 ★ 우수 사례를 체크할 수 있고, 엑셀의 ‘★ 우수 사례 문항’ 열에 정리됩니다.
- 과정 ③은 학생 화면에서 결과 칸과 결론 칸을 나누어 작성합니다.
